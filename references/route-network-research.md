# 单路线路网调研规范

在用户选定一条路线，并要求主线、下撤线、关键岔口、车辆点、决策点或截止点时读取本文件。输出结构化 JSON 和供人工审阅的 Markdown。JSON 是数据源，Markdown 是其可读视图；同一事实不得在两个文件中分别维护。

路网 JSON 使用 `TrailResearchData` 外层结构，至少包含 `route` 和 `route_network`。路网对象包含 `state`、`team_profile`、`nodes`、`edges`、`track_sources`、`track_segment_observations`、`decision_points`、`cutoff_points`、`vehicle_access_points`、`image_evidence`、`evidence` 和 `unresolved_items`。

## 一、路网边界

将路线表示为节点和有方向的路段：

- 节点包括起终点、岔口、营地、水源、风险点、决策点、下撤出口和车辆可达点。
- 路段连接两个节点，标明 `main`、`bailout`、`alternate` 或 `access`。
- 主线和每条候选下撤线都必须能从节点、路段及 GPX 来源还原。
- 地名相近不能作为合并节点的依据。默认仅在坐标相距不超过 100 米且地形关系一致时合并，并记录合并依据。

先画候选网络，再验证每个关键节点和路段。不要先写一条看似完整的叙述，再把缺少证据的位置隐藏在文字里。

## 二、两类状态

每个整线、节点、路段和车辆点分别保存以下两类状态。

### 证据成熟度

| 状态 | 含义 | 最低要求 |
|---|---|---|
| `Candidate` | 待验证候选 | 单一网络来源、未解析轨迹或坐标尚未交叉验证 |
| `Desk Verified` | 桌面验证 | 可解析 GPX 或精确坐标，加至少一个独立来源，且来源、日期和差异均有记录 |
| `Field Verified` | 实地验证 | 组织方人工踏勘，记录踏勘人、日期、自录轨迹或带位置的现场证据 |

不得根据“近期有人走过”、小红书实拍、商业队行程或多条转载内容标记 `Field Verified`。该状态只能由用户或组织方依据踏勘材料明确赋值。代码和模型不得自动晋级为 `Field Verified`。

`Desk Verified` 的默认交叉验证容差为：节点位置 100 米、路段距离 10%、累计爬升 15%。超过容差时保留不同结果，说明差异原因并维持 `Candidate`，除非有更高质量证据消解冲突。

### 当前开放状态

使用 `Open`、`Restricted`、`Closed`、`Unknown`。证据成熟度不代表当前开放状态；即使线路曾实地踏勘，也要单独核实最新封山、防火、施工和临时管控。

## 三、证据和时效

每条会影响路线选择的结论都引用 `evidence_id`，证据至少保存标题、平台、URL、形成日期、检索日期和它支持的具体结论。

建议时效窗口：

- 近期路况与岔路可通行性：30 天；暴雨、大雪、山火或施工后立即失效。
- 车辆可达与掉头条件：14 天，并在活动前 48 小时再次联系确认。
- 季节性水源：相同季节的记录，优先 14 天内；无法确认时按不可依赖处理。
- 政策与开放状态：优先官方最新通告，并在出发前再次核实。

窗口外证据不自动删除，但要降低当前性并列入 `unresolved_items`。

## 四、轨迹来源优先级、GPX 与两步路时间

### 来源优先级

在线轨迹按下列顺序检索、列示和选用：

1. 两步路用户上传轨迹；同层按 `recorded_at` 从新到旧，缺失时按 `uploaded_at` 从新到旧；
2. 六只脚等国内轨迹平台；
3. Wikiloc、AllTrails 等外部平台；
4. OSM、地图手工点位或文字推定。

组织方带日期、自录文件和位置照片的踏勘轨迹单列为最高证据等级。来源优先级决定先用哪条几何建立候选路网，验证成熟度仍按 `Candidate / Desk Verified / Field Verified` 独立判断。新轨迹不能仅因日期较近自动消除政策、季节或路线差异。

每条来源保存平台、轨迹 ID、记录日期、上传日期、检索日期、原链接、文件校验值、坐标系、适用路段和采用/降级原因。两步路和小红书结论必须链接原轨迹或原帖，转载页面只能作为补充。

### 路网 GPX 内容

GPX 不是原始来源的简单叠加，而是与 Markdown 对应的可读路网：

- 一条 `MAIN` track 表示计划主线；每条候选下撤为独立 `BAILOUT-*` track；每个路段保留原曲线，不跨缺失路段补直线；
- 下撤起点、下撤出口、Decision Point、Cut-off Point、关键岔口和车辆点均输出 waypoint，并使用与 JSON/Markdown 一致的 ID；
- Decision waypoint 写明计划到达区间、截止时间、继续/下撤边、触发条件和决定后动作；
- track segment 写明路段 ID、距离、爬升下降、计划时间区间、路况、验证状态及按优先级排列的原始来源链接；
- 两步路带位置路标照片能合法稳定引用时，waypoint 添加图片直链；否则添加原轨迹/标注页链接。图片缺失不阻止生成，但必须进入待核实清单；
- 主线或任一下撤边缺少至少两个真实轨迹点时，`scripts/route_network_gpx.py` 必须失败，不能以节点间直线代替。

完成后核对 GPX 的 `MAIN`、全部 `BAILOUT-*`、waypoint ID、Decision/Cut-off 时间、路况和来源，与 Markdown 表格逐项一致。

主线及每条下撤线分别记录轨迹平台、轨迹 ID、URL、记录/上传/检索时间、方向、里程、爬升下降、运动耗时、总耗时、GPX 可下载性和文件校验值。节点间切分结果另存为 `track_segment_observations`，包含轨迹 ID、路段 ID、运动时间、切分方法、可比性和排除原因，避免把整线耗时误配给多个路段。

时间提取遵循以下规则：

1. 每个关键路段尽量获取 3–5 条方向一致、季节与负重可比的轨迹。
2. 带时间戳的 GPX 可以在节点间切分运动时间；只有整线总时长的资料不能包装成路段时间。
3. 运动耗时与总耗时分开记录，不把长休息直接计入运动速度样本。
4. 排除越野跑、竞速、明显迷路或数据漂移样本，并记录排除原因。
5. 使用 P50–P85 区间，不使用最快记录安排普通队伍。

普通队员基准速度默认 2.5 km/h。单路段初始模型为：

```text
基础时间 = 距离 / 2.5 + 爬升 / 450 + 技术性陡降 / 700
模型时间 = 基础时间 × 路况系数 × 重装系数 × 队伍系数
```

建议起始系数：

| 因素 | 建议范围 |
|---|---:|
| 清晰土路/草甸 | 1.00–1.15 |
| 碎石陡坡、深草、泥泞或找路 | 1.20–1.60 |
| 重装 | 1.10–1.20 |
| 普通新手队伍 | 1.15–1.35 |
| Candidate 不确定性 | 上界再乘 1.15–1.30 |
| Desk Verified 不确定性 | 上界再乘 1.05–1.15 |
| Field Verified 不确定性 | 上界再乘 1.00–1.05 |

最终计划区间取模型结果与可比轨迹 P50–P85 的保守包络。必须在 JSON 中保存参数和方法版本，报告中说明样本数量与可比性。

## 五、Decision Point 和 Cut-off Point

Decision Point 必须对应真实节点，且继续主线和下撤分支均已明确。记录：

- 坐标、现场识别特征和信号；
- 主线与下撤线路段 ID；
- 各分支剩余距离、爬升下降和时间区间；
- 下撤终点及车辆接驳条件；
- 超时、天气、队员状态、政策或水源等触发条件；
- 做出决定后的统一行动。

Cut-off Point 使用剩余路段 P85 时间倒推：

```text
截止时间 = 安全到达时限 - 剩余路段 P85 - 固定缓冲 - 异常缓冲
```

安全到达时限结合日落、营地搭建、车辆等待和道路夜间通行条件。报告不得给出没有计算输入的固定时刻。用于正式执行的唯一主要下撤方案，其全部路段至少达到 `Desk Verified`；否则在报告中明确标为不可作为唯一安全保障。

## 六、车辆可达点

除坐标和导航关键词外，核实道路铺装、有效宽度、限高限重、会车、掉头、停车容量、雨雪影响、最后核实日期和适用车型。小车到达不能推导 25 座或更大车辆可达。网络资料只能形成候选或桌面判断，车型可达最好由司机或踏勘确认。

## 七、关键节点图片

图片用于识别岔口、营地、风险点和车辆点。每张图片记录节点 ID、来源链接、作者、拍摄/检索日期、拍摄方向、可见地物和复用状态。

优先顺序为：自有带位置踏勘照片、轨迹平台航点照片、官方资料、社交平台帖子。小红书等第三方图片默认 `link-only`，不要下载或复制进报告；链接失效风险写入未确认事项。网络图片不能把节点晋级为 `Field Verified`。

## 八、质量门槛

完成报告前运行结构校验，并人工检查：

- 节点和路段 ID 唯一，所有连接关系有效；
- 每个决策点至少有主线和候选下撤方向；
- 时间随距离、爬升、技术难度、负重和队伍系数合理增加；
- 截止时间保存安全到达时限、P85 和缓冲参数；
- 所有状态都可追溯到证据；
- 网上信息没有被标记为 `Field Verified`；
- `Closed` 或 `Unknown` 没有被摘要成“可正常通行”；
- 未确认事项单独汇总，注明人工核实方法和截止日期。
